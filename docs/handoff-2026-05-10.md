## Known gaps / open items

### Hard-blocked on user action

- **Stripe is OFF.** No keys, no webhook. Free chapters / signup / login / reading / coins balance display all work; `POST /payments/checkout/{coins,subscription}` returns 500 because no `STRIPE_SECRET_KEY` is configured. To onboard:
  1. Register at https://dashboard.stripe.com (region matters — China users typically go via Stripe HK / SG / JP / Atlas)
  2. Get test mode keys (`sk_test_…`, `pk_test_…`)
  3. Create products matching `COIN_PACKAGES` + `SUBSCRIPTION_PLANS` constants in `packages/shared/src/index.ts`
  4. Create webhook → `https://api.dramavela.com/payments/webhook` (test mode initially)
  5. Push `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET` to both Workers via `wrangler secret put`
- **PRODUCTION_DATABASE_URL_DIRECT not set** in GitHub repo secrets. This means `migrate-on-deploy.yml` is a no-op and prod schema migrations are run manually. To make migrations auto-fire on push to main: add the secret with the Supabase Sydney **Direct** (not pooler) connection URL, or skip if you prefer manual control.

### Soft / future work

- **No ICP filing for `dramavela.com`** — operates fine for global users; if you want to host long-term in mainland China you'd need ICP filing or a CN-hosted CDN frontend.
- **No Lighthouse / perf CI gate** — perf regressions could land silently. Add `lighthouse-ci` to `pr-checks.yml` or as a separate workflow if SEO becomes a priority.
- **No Slack/Discord deploy notifications** — deploy failures fire GitHub email only. Add a webhook step in `deploy-api.yml` / `deploy-web.yml` if needed.
- **OneSignal push, FB CAPI, Sentry** — env-gated, currently unset (or staging-set only). When ready, push the relevant secrets to the prod Worker.
- **Real cover artwork** — current covers (`apps/web/public/covers/*.svg`) are typographic SVGs. Replace with real artwork before launch if desired.
- **Admin user setup** — only the seeded `admin@novelhub.local / admin12345` admin exists. Create real admin accounts before opening to non-test users.

## Things to NOT do without explicit user confirmation

These are all in `docs/operations.md` but worth re-stating:

- Don't `wrangler r2 object delete` against prod bucket — explicit user authorization required (the `Object Read & Write` token allows it but please ask first).
- Don't run `wrangler rollback --env production` automatically on smoke failure — leave it for human eyes (the existing CI deliberately doesn't auto-rollback).
- Don't push secrets containing real credentials to chat — use `/root/.novelhub-secrets` (mode 600) + sourcing.
- Don't modify a migration file already in `packages/db/prisma/migrations/` — `db-migration-check.yml` will fail your PR.
- Don't enable Stripe Live mode without explicit user OK — Live mode is irreversible-ish (real payouts, identity verification).
- Don't merge PRs that touch `.github/workflows/` or `package.json` non-workspace deps without explicit human "merge X go" — `path_size_policy` flags these as policy-restricted on purpose.
